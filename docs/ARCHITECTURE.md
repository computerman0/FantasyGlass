# Architecture

`Core/` is a dependency-free Swift 6 package, shared by the app and tests. Decimal arithmetic, scoring rules, ESPN decoding, normalized entities, HTTP retry/cooldown handling, provider protocols and event detection live here. Models are Codable and Sendable; the network client is an actor. No UI state crosses into networking unsafely.

`App/` is a native SwiftUI application. An observable main-actor `AppModel` coordinates modular services and presents snapshots through five tabs. SwiftData persists one connection/snapshot per followed team, independent local scoring overrides, game caches and notification deduplication state. Failed network refreshes retain the previous persisted snapshot and its timestamp. Credentials live only in Keychain (or, after explicit setup consent, encrypted in the optional backend).

The scoring engine evaluates linear factors, per-whole-unit rules, thresholds and closed ranges. It uses provider stat identifiers losslessly, with a readable catalog. ESPN category counters already encode many yardage/distance/defense buckets; they must not be double-counted by synthesizing the same bonus. Local rules are separately editable and can reference any raw stat key. Position multipliers override a rule's default rate. Corrections replace the authoritative stat line rather than accumulating deltas. Every contribution remains available to inspect. A local override never makes an ESPN write request.

Fantasy and sports providers are separate interfaces. ESPN supplies league entities and raw stat lines. Its scoreboard supplies weekly NFL states. SportsDataIO can replace supported stat lines after explicit ESPN-to-SportsDataIO ID mapping; it never silently fuzzily matches names or mixes incompatible partial stat lines. Unsupported scoring coverage retains the original ESPN source with an explanatory warning. Adding Yahoo or Sleeper affects a provider adapter and credential setup, not the scoring engine.

`Shared/MatchupActivityAttributes.swift` is compiled in both the app and WidgetKit extension. The activity holds compact score strings and summaries, not player arrays. Dates in APNs content state use explicit Unix seconds. Live Activities are started in the foreground, updated locally after refresh, observed for token rotation/restoration, and linked by stable connection/matchup IDs. They expire under Apple's limits; a background worker cannot perpetually restart them. A separate notification device token is registered for alert pushes.

`Backend/` is an optional, single-owner Node 24 + TypeScript service using built-in SQLite, crypto, HTTP/2 and HTTPS. It authenticates every data endpoint with a high-entropy owner token, encrypts stored subscriptions/ESPN cookies with AES-256-GCM, limits request sizes/rates, and polls only fixed provider URLs. Persistent event fingerprints prevent duplicates across restarts. APNs token signing uses ES256 and a private `.p8` key loaded from a file. A reverse proxy terminates HTTPS; the process binds loopback by default. The backend computes ESPN local scores using decimal integer arithmetic and the uploaded local rule configuration. A test contract checks parity with Swift. A dedicated non-root host/service is recommended.

Foreground polling follows NFL game activity. Active games default to 60 seconds; idle polling backs off to 15 minutes. Background refresh is opportunistic, cancels on expiration and reschedules. Rate limits honor Retry-After with per-host cooldowns. HTTP credentials do not follow redirects. No fake background audio, location tracking, timers claimed to survive suspension, or private APIs are used.
